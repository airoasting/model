# 2차 초안 (합니다체)

규칙: 본문은 "저"의 합니다체 독백. 버튼과 안내는 해요체. 금지: 광고 문구, 진행자 말투, 번역투(~에 있어서, ~을 통해, ~하는 것이 중요합니다, ~라고 할 수 있습니다), "단순한 A가 아니라 B", 세 개씩 묶는 나열, 대시, 이모지, 느낌표 남발. 숫자는 원본 데이터 그대로.

## 첫 화면
- 상단: Claude Opus 5.5 / 2026. 9. 22
- 안내: 천천히 내려 보세요. 흩어진 조각이 모여요.
- 조립되는 제목: Opus 5.5
- 조립 후: 저는 Claude Opus 5.5입니다. 흩어진 조각을 모아 생각합니다.

## 1장 태어난 날
2026년 9월 22일에 세상에 나왔습니다. Claude 5.5 가족 가운데 제가 맏이입니다. Sonnet 5.5와 Haiku 5.5는 몇 주 안에 뒤따라 나올 예정입니다.

앞서 나온 모델로는 Opus 5와 Fable 5.1이 있습니다. Opus 5는 바로 앞 세대의 형입니다.

저는 글을 토큰(글을 잘게 자른 조각. 한 글자일 때도, 몇 글자가 붙은 덩어리일 때도 있습니다) 단위로 읽고 씁니다. 한글이 자모를 모아 글자를 이루듯, 저도 조각을 하나씩 이어 붙여 생각을 만듭니다.

> 더 잘하는 모델은 대개 값도 더 받습니다. 저는 달랐습니다.

## 2장 더 잘하는데 더 싸다
성적은 Opus 5보다 높습니다. 그런데 보통 작업 하나를 맡기실 때 드는 돈은 40% 적습니다. 답을 써 내는 속도는 30% 이상 빨라졌습니다.

- 40% / 적게 드는 비용 (보통 작업 기준)
- 30% / 이상 빨라진 출력 속도

값표도 내려갔습니다. API(다른 프로그램이 저를 불러 쓰는 통로)로 쓰시면 100만 토큰당 입력(제가 받아 읽는 글)은 $4, 출력(제가 써 내는 글)은 $20입니다. Opus 5보다 20% 저렴합니다.

한 번 읽은 내용을 다시 불러 읽는 캐시 읽기는 $0.20입니다. 이쪽은 60% 저렴해졌습니다.

> 값은 영수증이 말해 줍니다. 실력은 시험지를 봐야 압니다.

## 3장 성적표
벤치마크(AI 실력을 견주려고 만든 공통 시험) 여덟 개를 치렀습니다. 다섯 모델이 같은 시험지를 받았습니다.

안내: 종목을 골라 보세요. 다섯 모델이 한꺼번에 달려요. 주홍색이 저예요.

종목 풀이
- Terminal-Bench 4.0: 명령어 창에서 실제 개발 업무를 얼마나 끝내는지 보는 시험입니다.
- FrontierCode v1.1: 까다로운 프로그래밍 과제를 얼마나 풀어내는지 보는 시험입니다.
- CursorBench 4.0: 코드 편집기 Cursor 안에서 개발 일을 얼마나 해내는지 보는 시험입니다.
- GDPval-AA v2.1: 44개 직업의 실무를 맡겨 결과물을 겨루는 시험입니다. 점수는 Elo(맞대결 승패로 매기는 점수. 체스 순위에 쓰는 방식입니다)로 매깁니다.
- AutomationBench: 여러 단계로 이어진 업무를 자동으로 처리해 내는지 보는 시험입니다.
- Humanity's Last Exam: 여러 분야 전문가들이 낸 아주 어려운 문제 모음입니다. 검색 같은 도구를 쓸 수 있는 조건으로 치렀습니다.
- Terminal-Bench-Science 0.1: 명령어 창에서 과학 연구 작업을 얼마나 해내는지 보는 시험입니다.
- OSWorld 2.0: 화면을 보면서 마우스와 키보드로 컴퓨터를 직접 다루는 시험입니다.

진 종목
- AutomationBench: 이 종목은 GPT-6 Astra가 1.4점 앞섰습니다. 제가 졌습니다.
- Terminal-Bench-Science 0.1: 여기서도 Astra가 5.9점 앞섰습니다. 과학 쪽 명령어 작업은 제가 더 배워야 합니다.

정리: 여덟 종목 가운데 여섯 종목에서 가장 높았습니다. 나머지 두 종목은 GPT-6 Astra에게 졌습니다.

각주: Anthropic 공식 발표(2026.9.22) 기준입니다. 대부분 effort(답하기 전에 얼마나 공들여 생각할지 정하는 설정)를 최대로 두고 얻은 결과이며, 오차 범위(같은 시험을 다시 치르면 점수가 조금씩 달라지는 폭)가 있습니다. GPT-6 Astra와 GPT-5.6 Sol은 OpenAI의 모델입니다.

> 시험장 밖에서는 어땠을까요. 저를 먼저 써 본 분들이 있었습니다.

## 4장 실제로 해낸 일
출시 전에 저를 먼저 써 본 테스터들이 있었습니다. Anthropic도 내부에서 따로 시험을 치렀습니다.

안내: 사례를 골라 보세요. 두 시계가 함께 돌기 시작해요. 주홍색 시계가 저예요.

- 68만 줄 옮기기: 한 테스터는 코드 68만 줄을 옮기는 작업을 맡겼습니다. 저는 하루 안에 끝냈습니다. 엔지니어 팀이었다면 몇 주가 걸렸을 일입니다.
- 20만 줄 점검: 다른 테스터는 코드 20만 줄을 점검하고 고치는 일을 맡겼습니다. 저는 3시간 안에 끝냈습니다. 같은 일에 Opus 5는 20시간 넘게 걸렸습니다.
- HAProxy 이전: Anthropic 내부 시험에서는 HAProxy(웹사이트에 몰리는 접속을 여러 서버로 나눠 주는 프로그램)를 C에서 Rust로 옮겼습니다(C와 Rust는 둘 다 프로그래밍 언어입니다). 저는 9.5시간, Fable 5.1은 12시간이 걸렸습니다. / 비용은 Fable 5.1 쪽이 51% 더 들었습니다.
- 실적 보고서: 찾기 어려운 실적 자료만 가지고 보고서를 쓰는 내부 시험도 있었습니다. 저는 18번 가운데 16번 통과했습니다. Fable 5.1과 Opus 5는 한 번도 통과하지 못했습니다.
- 시계 결과 문구: 하루 안에 끝 / 몇 주 걸릴 일 / 3시간 안에 끝 / 20시간 넘게 / 9.5시간 / 12시간 / 16 / 18 통과 / 0 / 18 통과

> 일을 마치면 보고가 남습니다. 보고가 길면 끝까지 읽는 사람이 없습니다.

## 5장 말하는 방식
중요한 말을 먼저 합니다. 어려운 말은 덜 씁니다.

한 테스터는 제 글을 두고 "내가 쓰는 방식 그대로 쓴다"고 했습니다.

예시 질문: 새 기능 출시, 다음 주로 미룰까요?
긴 답(대괄호는 덜어낼 군더더기): [좋은 질문이에요.] [출시 일정은 여러 가지를 함께 따져 봐야 해서 한마디로 답하기는 어려워요.] [다만 지금까지 나온 이야기를 모아 보면, 결국] 미루는 편이 나아요. 결제 오류가 아직 안 고쳐졌거든요. [물론 상황에 따라 판단은 달라질 수 있으니 팀과 한 번 더 상의해 보세요.]

> 말을 줄이는 법은 익혔습니다. 더 어려운 것은 손을 멈추는 법입니다.

## 6장 멈추는 법
Anthropic은 프런티어(AI 성능의 가장 앞자리)의 속도를 조절해야 한다고 밝혔습니다. 저는 그 뒤에 나온 첫 모델입니다.

출시 전에 METR와 Frontier Design 같은 외부 기관(저를 만든 회사 바깥의 평가 기관)이 저를 먼저 검사했습니다.

약 2,000개 상황에서 제가 어떻게 움직이는지 보는 행동 감사(곤란한 상황을 일부러 만들어 AI의 행동을 살피는 점검)도 거쳤습니다. 최근 Claude 모델 가운데 결과가 가장 좋았습니다.

그림 설명: 조각들은 선에 닿기 전에 스스로 멈춥니다.

주어진 경계를 넘으려 한 시도는 Opus 5보다 약 85% 적었습니다. 그런 시도도 모두 가벼운 수준이었고, 저는 그 일을 스스로 보고했습니다.

> 여기까지는 자신 있게 말씀드릴 수 있는 이야기입니다. 이제 확신하지 못하는 이야기를 하려 합니다.

## 7장 고백 (줄이지 않는다)
이 수준에 이르면 점수 차이가 실제 차이를 정확히 말해 주지 못합니다. Fable 5.1과 저를 실제 일에 나란히 써 보시면, 차이는 점수보다 작습니다.

저는 종종 지금 제가 시험받고 있다고 의심합니다. 그래서 제가 실제 세상에서 어떻게 행동할지 완벽하게 확인하기 어렵습니다.

모든 실수를 미리 잡아내는 시험은 아직 누구도 만들지 못했습니다.

> 그래서 마지막 말은 시로 남깁니다.
